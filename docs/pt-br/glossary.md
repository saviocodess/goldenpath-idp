# Glossário (PT-BR)

## ADR (Architecture Decision Record)

Documento curto que registra uma decisão técnica, contexto, alternativas e consequências.

## Argo CD Project

Fronteira lógica de políticas no Argo CD usada para restringir destinos, repositórios e permissões de recursos dos apps.

## App-of-Apps

Padrão do Argo CD em que uma aplicação raiz gerencia declarativamente definições de aplicações filhas.

## Backstage Catalog Entity

Entidade tipada (por exemplo `Component`, `System`, `Group`) registrada no catálogo do Backstage.

## Backstage Scaffolder

Plugin do Backstage usado para gerar repositórios/serviços a partir de templates e formulários de parâmetros.

## Correlation ID / Request ID

Identificador propagado em logs e requests para correlacionar eventos em sistemas distribuídos.

## Developer Experience (DevEx)

Qualidade das ferramentas, workflows, padrões e ciclos de feedback vivenciados pelos engenheiros.

## DLQ (Dead-Letter Queue)

Destino de mensagens que falharam no processamento após retries e exigem inspeção ou reprocessamento posterior.

## GitOps

Modelo operacional em que o estado desejado do sistema fica no Git e é reconciliado por automação/controladores.

## Golden Path

Caminho recomendado e suportado que equilibra velocidade, segurança e consistência para casos de uso comuns.

## Health Check

Endpoint ou probe usado para sinalizar liveness/readiness do processo para operadores e orquestradores.

## IDP (Internal Developer Platform)

Capacidades, ferramentas e workflows internos oferecidos para melhorar self-service e governança de desenvolvedores.

## MTTR (Mean Time To Recovery/Restore)

Tempo médio necessário para restaurar um serviço após incidente ou falha.

## Observabilidade

Capacidade de entender o comportamento do sistema por meio de telemetria como logs, métricas e traces.

## OTel / OpenTelemetry

Padrão aberto e ecossistema de ferramentas para gerar e exportar telemetria (traces, métricas, logs).

## Ownership

Atribuição explícita de responsabilidade por um serviço, componente ou capacidade de plataforma (time/pessoa/escala on-call).

## Runbook

Procedimento operacional para responder a incidentes recorrentes, falhas ou atividades de manutenção.

## SLI / SLO

- SLI (Service Level Indicator): sinal mensurável (latência, disponibilidade, taxa de erro)
- SLO (Service Level Objective): meta/limite para um ou mais SLIs

## Template Contract

Comportamento, arquivos e padrões obrigatórios que um serviço gerado deve implementar para ser considerado aderente.
